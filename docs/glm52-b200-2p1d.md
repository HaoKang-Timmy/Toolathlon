# GLM-5.2 FP8 on three B200 nodes: P-side CP=8, 2P1D, Mooncake, and D-side MTP=3

This document is the reproducibility contract for the Toolathlon scale run. It
describes the exact cluster roles, shared artifacts, SGLang code, parallelism,
PD transfer path, observability settings, and validation order. The experiment
driver under `experiments/glm52_2p1d/` is expected to implement this contract.

## Target topology

| Role | SSH name | Data-plane IP | GPUs | HTTP port | Bootstrap port |
| --- | --- | --- | --- | --- | --- |
| Decode and control | `b200-dev` | `10.0.10.96` | 8 x NVIDIA B200 | `30001` | n/a |
| Prefill 0 | `b200-dev-2` | `10.0.12.131` | 8 x NVIDIA B200 | `30000` | `8998` |
| Prefill 1 | `b200-dev-3` | `10.0.5.63` | 8 x NVIDIA B200 | `30000` | `8998` |
| PD router | `b200-dev` | `10.0.10.96` | CPU only | `8000` | n/a |

The decode node is also the control plane. It launches and checks both remote
prefill processes over SSH, runs the PD router, runs Toolathlon, polls all
metrics endpoints, and writes all experiment output to the shared PVC.

All three nodes have the same validated hardware baseline:

- 8 x NVIDIA B200 with 183359 MiB per GPU
- NVIDIA driver `595.58.03`
- 8-GPU NVLink fabric (`NV18` peer links)
- 12 active physical `mlx5` InfiniBand functions plus `mlx5_bond_0`
- shared PVC mounted at `/mnt/shared`

by all three nodes. Do not copy or relocate it: virtual environments contain
absolute paths. Update it once from the decode node, then validate imports on
all three nodes.

```bash

uv pip install --python "${SGLANG_ENV}/bin/python" \
  mooncake-transfer-engine \
  sglang-router \
  nvidia-cuda-runtime-cu12

# Run on all three nodes for Mooncake's RDMA userspace dependencies.
sudo apt-get install -y libibverbs1 ibverbs-providers rdma-core
```

Validate the same environment from every node:

```bash
for host in b200-dev b200-dev-2 b200-dev-3; do
```

## Mooncake RDMA mapping

`nvidia-smi topo -m` is identical on the three nodes. The primary GPU-local
mapping is:

| GPU | Local HCA |
| --- | --- |
| 0 | `mlx5_0` |
| 1 | `mlx5_1` |
| 2 | `mlx5_2` |
| 3 | `mlx5_3` |
| 4 | `mlx5_4` |
| 5 | `mlx5_5` |
| 6 | `mlx5_10` |
| 7 | `mlx5_11` |

The extra functions on GPU 6 are separate physical PCI functions with PIX
locality. `mlx5_bond_0` is not passed to Mooncake. Before every deployment,
the launcher must check that every selected RDMA link is `ACTIVE` and
`LINK_UP` with `rdma link`.

The SGLang argument is a per-GPU JSON mapping:

```bash
IB_MAP='{"0":"mlx5_0","1":"mlx5_1","2":"mlx5_2","3":"mlx5_3","4":"mlx5_4","5":"mlx5_5","6":"mlx5_10","7":"mlx5_11"}'
```

Do not include `mlx5_6` through `mlx5_9` in the cross-node map. On these
systems those four HCAs have node-local LIDs (`1` through `6`) and are not on
the external fabric; using them for GPU6 causes RDMA QPs to exhaust their
transport retry counter. GPU6's external HCA is `mlx5_10`.

Both prefill servers and the decode server must use the same transfer backend
and topology:

```bash
--disaggregation-transfer-backend mooncake \
--disaggregation-ib-device "${IB_MAP}"
```

## Parallelism contract

Every model instance occupies all eight GPUs on its node. The role-specific
attention parallelism is:

```text
P0/P1: tp_size=8, attn_cp_size=8, ep_size=8, moe_dp_size=1
D:     tp_size=8, attn_cp_size=1, ep_size=8, moe_dp_size=1
```

The two prefill servers enable the complete DSA prefill CP path:

```bash
--tp-size 8 \
--attn-cp-size 8 \
--enable-prefill-cp \
--cp-strategy interleave \
--enable-dsa-cp-shared-kv-cache
```

All three SGLang processes must also export
`SGLANG_DISAGGREGATION_ALL_CP_RANKS_TRANSFER=1`.  With CP-shared VMM KV, each
CP rank registers only its GPU-local allocation with Mooncake and sends the
logical pages it owns; the decode server waits for and combines all eight
responses.  Registering the rank-0 global VMM span is invalid for GPUDirect
RDMA because seven of its mappings are imported from peer GPUs.

The decode server keeps `--tp-size 8` but uses `--attn-cp-size 1`. This is a
hard constraint of the pinned PR's PD rank mapper: it gathers the CP-sharded
prefill cache into a non-attention-CP decode engine and asserts that decode
attention CP is 1. Decode still uses all eight GPUs through TP=8. CUDA DCP=8 is
not a substitute here because this revision rejects CUDA DCP together with
speculative decoding, while this experiment requires D-side MTP=3.

## MTP/EAGLE contract

The decode engine performs continuous speculative drafting with:

```bash
--speculative-algorithm EAGLE \
--speculative-draft-model-path /mnt/shared/glm52/models/GLM-5.2-FP8 \
--speculative-num-steps 3 \
--speculative-eagle-topk 1 \
--speculative-num-draft-tokens 4 \
--speculative-moe-runner-backend flashinfer_trtllm
```

The prefill engines must use matching EAGLE metadata settings. This makes the
PD hidden-state/top-k metadata buffer layout identical on P and D and allows
the D engine to seed MTP after the target prefill. The P engines remain
prefill-only; the D engine owns ongoing draft, verify, and decode scheduling.

## Common model arguments

Use these on P0, P1, and D unless a role-specific section says otherwise:

```bash
--model-path /mnt/shared/glm52/models/GLM-5.2-FP8 \
--served-model-name glm-5.2 \
--quantization fp8 \
--tp-size 8 \
--moe-dp-size 1 \
--ep-size 8 \
--moe-a2a-backend none \
--moe-runner-backend flashinfer_trtllm \
--attention-backend dsa \
--dsa-prefill-backend flashmla_sparse \
--dsa-decode-backend flashmla_kv \
--dsa-topk-backend sgl-kernel \
--kv-cache-dtype fp8_e4m3 \
--context-length 262144 \
--chunked-prefill-size 32768 \
--mem-fraction-static 0.85 \
--tool-call-parser glm45 \
--reasoning-parser glm45 \
--trust-remote-code \
--disable-shared-experts-fusion \
--disable-custom-all-reduce \
--enable-metrics \
--enable-metrics-for-all-schedulers
```

Memory and concurrency values are initial settings, not claims of a validated
maximum. The smoke test may lower `mem-fraction-static`, max running requests,
or CUDA graph sizes if the MTP worker leaves insufficient headroom.

## Role-specific launch shape

### P0 on `b200-dev-2`

Launch the common arguments plus:

```bash
--host 0.0.0.0 \
--port 30000 \
--disaggregation-mode prefill \
--disaggregation-bootstrap-port 8998 \
--attn-cp-size 8 \
--enable-prefill-cp \
--cp-strategy interleave \
--enable-dsa-cp-shared-kv-cache
```

Interleave is required here because Toolathlon has batched prefill. Zigzag DSA
CP forces DeepEP and is explicitly restricted to batch size 1 in this
revision; interleave keeps the configured non-A2A FlashInfer MoE runner.

### P1 on `b200-dev-3`

Use the same role-specific arguments as P0. The duplicate HTTP and bootstrap
ports are safe because the two processes are on different hosts.

### D on `b200-dev`

Launch the common and MTP arguments plus:

```bash
export SGLANG_JIT_DEEPGEMM_FAST_WARMUP=1

--host 0.0.0.0 \
--port 30001 \
--disaggregation-mode decode \
--attn-cp-size 1
```

Do not add `--enable-prefill-cp` or `--enable-dsa-cp-shared-kv-cache` to D.
The D workload has at most 48 running requests and four speculative tokens per
verification step, so the fast warmup's dense GEMM grid through M=1024 covers
its measured decode shapes while avoiding the full prefill-sized JIT sweep on
every D recovery.

### Router on `b200-dev`

After all three engines are healthy, expose one OpenAI-compatible endpoint:

```bash
/mnt/shared/glm52/sglang-v0513/bin/python -m sglang_router.launch_router \
  --pd-disaggregation \
  --prefill http://10.0.12.131:30000 8998 \
  --prefill http://10.0.5.63:30000 8998 \
  --decode http://10.0.10.96:30001 \
  --policy cache_aware \
  --host 127.0.0.1 \
  --port 8000
```

Toolathlon uses `http://127.0.0.1:8000/v1` and never targets P or D directly.

## Validation order

Do not start the full benchmark immediately after the processes appear.
Validate in this order:

1. Verify model files, environment imports, source revision/diff, all eight
   GPUs, and all selected RDMA links on every node.
2. Start P0 and P1; wait for both `/health` endpoints and inspect logs for
   `attn_cp_size=8`, prefill CP, shared KV, and Mooncake initialization.
3. Start D; verify `attn_cp_size=8`, EAGLE steps 3, draft tokens 4, and the
   absence of the decode/prefill-CP assertion.
4. Start the router and require all three workers to be registered.
5. Send one short non-tool streaming request and one tool-schema request.
6. Confirm that P-to-D transfer counters change and no TCP-only fallback or
   Mooncake error appears in any log.
7. Confirm `/metrics` exposes request latency histograms, prompt/generation
   counters, cache hit data, and per-scheduler token usage.
8. Flush runtime caches on P0, P1, and D before each measured Toolathlon run.

## Experiment and persistence contract

Run the full fixed `finalpool` task set once at each configured Toolathlon
worker limit: 16, 32, 48, and 64. Use a distinct PVC directory for every level
so Toolathlon's resume logic cannot skip tasks from a previous level.

```text
/mnt/shared/glm52-stack/toolathlon-runs/glm52-2p1d/<run-id>/
  manifest/
  concurrency-16/
  concurrency-32/
  concurrency-48/
  concurrency-64/
  reports/
```

For every LLM request, retain request ID, task ID, attempt, timestamps, TTFT,
TPOT, prompt/prefill tokens, cached prompt tokens, uncached prompt tokens,
decode tokens, finish reason, status, and error. Raw request metrics and
trajectories are append-only JSONL/JSON files on the PVC.

At experiment start, experiment end, and every 300 seconds in between, retain:

- `nvidia-smi` GPU utilization, memory, power, temperature, and clocks for all
  24 GPUs;
- SGLang `token_usage`, `num_used_tokens`, full token usage, cache hit rate,
  pending preallocation usage, queue/running counts, and token counters for all
  scheduler ranks;
- router and worker health;
- actual Toolathlon active/running/waiting worker counts.

Aggregate TTFT and TPOT from per-request records. Prometheus histogram deltas
are retained as an independent cross-check. Aggregate cache hit rate is
`sum(cached_prompt_tokens) / sum(prompt_tokens)`, rather than an unweighted
average of per-request percentages.

Each concurrency level starts from flushed runtime KV/radix caches. It stores
its own raw trajectories, raw metric samples, task outcomes, tool-call counts,
tool-name distribution, request distributions, GPU distributions, and a
machine-readable summary. A combined report compares all four levels.

The checked-in automation for this exact topology is under
`experiments/glm52_2p1d`. A one-task smoke test and the full run are:

```bash
uv run experiments/glm52_2p1d/run_suite.py --run-id smoke-$(date -u +%Y%m%dT%H%M%SZ) --smoke
uv run experiments/glm52_2p1d/run_suite.py --run-id full-$(date -u +%Y%m%dT%H%M%SZ)
```

The first command deploys all workers and the router. For the second command,
add `--reuse-cluster` only after checking the retained server logs and health.

## Failure policy

The primary objective is to finish all four levels and collect complete
traces. A failure triggers diagnosis, repair, and bounded retry with all failed
attempt logs preserved. Do not replace an ordinary failure with an idle job.

Only after reasonable in-scope repair paths are exhausted and the remaining
blocker is external or cannot be corrected in the current environment may the
automation launch clearly labeled idle placeholder jobs on all three nodes.
Placeholder output must be stored separately and must never be reported as a
Toolathlon result.
